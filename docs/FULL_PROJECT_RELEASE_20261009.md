## تشغيل الإنتاج

النشر يستهدف خدمات Render القائمة `xmansx-core` و`xmansx-web` فقط، من `main`،
دون إنشاء موارد أو شراء خطط أو تغيير DNS. الرابط الحالي:
`https://xmansx-web.onrender.com`. النطاق `xmansx.com` لمشروع آخر؛ إرسال البريد
يستخدم `mail.mowadhabah.com` وعنوان `recovery@mail.mowadhabah.com`.

أذن المستخدم بنقل مفتاح Resend المقيد الموجود إلى أسرار `xmansx-core`، وتفعيل
التفعيل والاسترداد للأهل وحسابات المدرسة. لا مفتاح داخل Git أو image أو تقرير.
بريد الاشتراكات التلقائي يبقى معطلاً؛ لا رسائل اختبار بريد أوSMS إضافية في
عملية النشر. إعداد إرسال الدعوات المدرسية لا ينشئ إرسالاً جماعياً تلقائياً؛
كل دعوة تتطلب مراجعة المدير/الوكيل وربط الأبناء وتحقق صلاحية المزود والميزانية.

أُنشئت قبل النشر نسخة إنتاجية ناجحة رقم39، حجم3378957بايت، ببصمة
`32a8a2f0ce1cec5db529a199755c6bee964dda1721224eb61797599aa1042d8a`،
مدة5386ms. التحقق من Runtime السابق أثبت remote backup مطلوباً ومفعلاً،
ودور قاعدة البيانات `(rolsuper=False, rolbypassrls=False)`. لا استعادة على
الإنتاج أو تغيير بيانات طلاب. ظهور تنبيه دفع في Render ليس إثباتاً لفشل نشر؛
لا يعالج الإصدار بيانات الدفع أو يشتري موارد.

قبل اعتماد النشر يلزم إثبات SHA الحي للخدمتين، اكتمال migrations الجديدة،
readiness، heartbeat العامل والجدولة، RLS، صحة origin وإعدادات البريد المقنعة،
وتطابق assets/PWA مع الصورة الجديدة. لا تكفي HTTP200 وحدها.

## حدود تشغيلية محفوظة

لا تغيير لقواعد SMS الغياب أو Dreams/Msegat أو مصدر `Student.guardian_mobile`،
ولا اشتراط حساب/بريد ولي أمر لاستحقاق SMS. لا استئذان إلكتروني للأهل؛ يستمر
الاستئذان الإداري والحارس. تغيير الجوال العالمي والاستعادة المركزية غير المعتمدة
يبقيان مغلقين. لا تدوير لمفاتيح التشفير/HMAC الحالية.

لا يثبت هذا الإصدار قدرة2000مستخدم: تجربة السعة الصناعية السابقة سجلت
43.61%فشل ولم تحقق الهدف. الملف scalable تحضير منفصل، وليس إذناً لزيادة
التكلفة. بقيت تشخيصات OpenAPI القديمة معلنة في تقارير التحقق؛ نجاح generation
لا يعني اختفاءها. وصول رسالتي Resend الصناعيتين السابق كان إلى Spam؛ لا
ادعاء قبول Inbox أو إرسال رسالة إنتاجية إضافية في هذه المهمة.

الرجوع يكون Forward fix أو إصدار متوافق يحتفظ بحراس الحساب واعتمادات البريد
وRLS. يمنع الرجوع إلى Backend يعيد فتح reset الإداري القديم، أو reverse
لهجرات تحذف علاقات واعتمادات فعلية. لا تستخدم force reset/push أو fake migrations.
