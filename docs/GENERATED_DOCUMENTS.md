# المستندات المولدة (المرحلة 12)

`GeneratedDocument` نسخة **مجمدة** من مستند رسمي كما صدر وقتها. القاعدة الحاكمة:

```
إنشاء → تجميد اللقطة → توليد PDF → تخزين خاص → READY
إعادة طباعة → إعادة الملف المخزن نفسه (لا توليد جديد)
```

مثال حاسم: صدر الإنذار الثاني عند **5 أيام** غياب بدون عذر، ثم صار الحالي 8 أو
انخفض إلى 3 بعذر معتمد — إعادة الطباعة تعطي **5** دائمًا، ونفس البايتات ونفس
`checksum` (مثبت بالاختبارات وبـE2E).

## اللقطة

`snapshot_data` (JSON) تحوي ما يكفي لفهم المستند وإعادة رسمه وحده:

- المدرسة: الاسم، الرقم الوزاري، المدينة، اسم المدير الرسمي من `SchoolSettings`؛
  وإن كان فارغاً فاسم صاحب دور مدير المدرسة ذي العضوية الفعالة، لا المستخدم الحالي.
- الطالب: الاسم والصف والفصل ورقم الهوية **مقنّعًا** — لا رقم هوية صريح.
- بيانات المستند: قيم الإنذار وقت الإصدار، أو مقاييس الفترة، أو صفوف الكشف.
- الفترة، وقت الإنشاء ومن أنشأه، ومعرّف القالب وإصداره ونوع مصدره.

مستندات الإنذار تُبنى من لقطة `StudentWarning` **وحدها** — ولا استعلام مقاييس واحد
(مثبت بعدّاد استعلامات). لذلك تغيير قواعد الإنذارات أو الأعذار أو نقل الطالب أو
تغيير اسمه لا يمس مستندًا صدر.

`snapshot_schema_version` (=1) يسمح بقراءة مستندات قديمة بعد تطور بنية اللقطة،
و`template_version` يثبت القالب الذي رسمها.

## أنواع المستندات

| النوع | المصدر | يحتاج مدى تواريخ |
|---|---|---|
| `WARNING_LEVEL_1/2/3` | لقطة الإنذار | لا |
| `ATTENDANCE_COMMITMENT` | مقاييس الفترة وقت الإنشاء | نعم |
| `ABSENCE_DETAIL_REPORT` | `DailyAttendanceSummary` | نعم |
| `MORNING_LATE_DETAIL_REPORT` | `SchoolArrival` | نعم |
| `PERIOD_LATE_DETAIL_REPORT` | `AttendanceMark.LATE` | نعم |
| `STUDENT_ATTENDANCE_REPORT` | الملخص + الإنذارات + الإجراءات | نعم |

التأخر الصباحي وتأخر الحصص **عدّادان منفصلان** لا يجمعان في أي مستند. اليوم
المختلط يعرض «مختلط (بعذر وبدون عذر)» بأرقامه، واليوم الناقص «بيانات التحضير غير
مكتملة» ولا يعد غيابًا كاملًا. تقرير المواظبة **بلا أي بيانات إرشاد/إحالات** (م13).

## مسار الإنشاء الآمن

1. صف `PENDING` مع اللقطة داخل `transaction` — القيد الفريد الجزئي يمنع النسخة
   الثانية قبل أن يبدأ أي توليد.
2. رسم HTML من القالب المثبت ← PDF ← حفظ الملف (خارج الـtransaction).
3. `READY` مع `size_bytes` و`checksum` (SHA-256) و`generated_at`، أو `FAILED`
   برمز آمن (`DOCUMENT_RENDER_FAILED` / `PDF_ENGINE_UNAVAILABLE`) وبلا ملف.

قيد `document_ready_requires_file` يمنع قاعدة البيانات من قبول `READY` بلا ملف —
لا ادعاء جاهزية بأي حال.

## التكرار وإعادة الإصدار

قيد فريد جزئي على (`warning`, `document_type`, `revision`) للحالات الحية
(`PENDING`/`READY`): النقر المزدوج ⇒ مستند واحد و`DOCUMENT_ALREADY_EXISTS` (409).
المستند الملغى **لا يحجز** المكان، فيمكن إصدار نسخة أصلية جديدة بعد إلغاء الأولى
— وهذا هو المسار الصريح لإعادة الإصدار، لا نسخ متعددة صامتة.

## إعادة المحاولة وإعادة الطباعة

- `POST /documents/{id}/retry/`: للمستندات `FAILED` فقط، ويعيد الرسم من **اللقطة
  المخزنة** — لا يقرأ بيانات الطالب الحالية (مثبت باختبار يغيّر البيانات بين
  المحاولتين). غير ذلك ⇒ `DOCUMENT_NOT_READY` (409).
- إعادة الطباعة = تنزيل الملف المخزن. **لا توليد صامت** من البيانات الحالية.
- ملف مفقود من التخزين مع بقاء الصف ⇒ `DOCUMENT_FILE_MISSING` (409) وحالة المستند
  لا تُزوَّر. الاسترجاع (إعادة رسم من اللقطة) عملية صريحة يقررها المشغل عبر
  `retry` بعد نقل الحالة يدويًا — لا مسار تلقائي.

## التخزين والتنزيل

- الملفات خارج `MEDIA_ROOT` في `GENERATED_DOCUMENTS_ROOT` (إعدادات التطوير تخدم
  `MEDIA_URL` عبر HTTP، فأي ملف داخلها يصبح عامًا).
- مخزن خاص يرفض `url()` صراحةً: لا رابط عام دائم حتى بالخطأ البرمجي.
- مفتاح التخزين عشوائي: `school_{id}/{uuid}.pdf` — لا اسم طالب ولا نوع مستند في
  المسار. (`storage_key` = `file.name`.)
- التنزيل الوحيد عبر `GET /documents/{id}/download/`: مصادق، مقيّد بالمستأجر
  والدور، ولا يخدم إلا `READY`.
- `checksum` يثبت أن المعاد طباعته هو الملف الأصلي نفسه.

## الواجهات

```
GET  /api/v1/documents/?student=&document_type=&warning=&status=
POST /api/v1/documents/preview/     ← معاينة البيانات قبل الإصدار
POST /api/v1/documents/generate/
GET  /api/v1/documents/{id}/
GET  /api/v1/documents/{id}/download/
POST /api/v1/documents/{id}/retry/
POST /api/v1/documents/{id}/void/
```

**العميل يرسل نية فقط**: `student_id` و`document_type` و`warning_id` والمدى. أي
قيمة لقطة مرسلة (`metric_value_at_issue`, `snapshot_data`, `template_version`,
`status`) تُتجاهل — الخادم يعيد بناء كل شيء (مثبت باختبار حقن).

## الأداء

قياس (`benchmark_documents`) على حاوية التطوير:

| العملية | الزمن |
|---|---|
| مستند إنذار | 819ms |
| تعهد حضور | 288ms |
| كشف غياب 30 صفًا | 575ms |
| كشف غياب 100 صف | 1.9s |
| كشف غياب 300 صف | 4.0s |
| رسم 500 صف (22 صفحة) | 6.2s |
| بناء لقطة 300 صف (بلا PDF) | 18ms |
| قائمة المستندات/الإجراءات (25) | 8-11ms — **استعلام واحد** |

الاستعلامات ليست العنق: الرسم ~250ms لكل صفحة A4 (تجربة CSS بديلة لم تغير شيئًا
يذكر). لذلك `MAX_REPORT_ROWS = 500` حارس مضبوط بالقياس؛ الفترات الأطول تقسم.

## التدقيق والحذف النهائي

`DOCUMENT_GENERATION_REQUESTED` و`DOCUMENT_GENERATED` و`DOCUMENT_GENERATION_FAILED`
و`DOCUMENT_VOIDED` و`DOCUMENT_DOWNLOADED` — معرفات وأنواع وأحجام فقط: **لا محتوى
PDF ولا لقطة كاملة**. الحذف النهائي: خطوة «المستندات المولدة» أولًا في
`PURGE_STEPS`، وملفات PDF تُحذف من التخزين عبر
`PURGE_STORAGE_COLLECTORS`. القوالب ليست بيانات طالب فلا تحذف.

## التكامل مع الإحالات (م13)

إنشاء إحالة أو تعيين مرشد أو استلام الحالة **لا يمس** مستندًا صادرًا: نفس البايتات
ونفس `checksum` ونفس اللقطة (اختبار خلفي + E2E). وبالمقابل، وجود إحالة **لا يمنح**
المرشد تنزيل المستند — الصلاحيات تبقى لكل ميزة على حدة.

## حدود معروفة

- التوليد متزامن داخل الطلب: تقرير 500 صف يحجز عاملًا ~6 ثوانٍ. النموذج يدعم
  `PENDING` فعليًا، فنقل الرسم إلى Celery تغيير محصور (دين موثق).
- لا شعار مدرسة داخل المستندات: تضمين صورة يجعل اللقطة غير مكتفية بذاتها أو يربطها
  بملف قد يتغير. الترويسة نصية (اسم/رقم وزاري/مدينة).
- لا توقيع رقمي ولا ختم — أماكن توقيع فارغة للطباعة فقط.
