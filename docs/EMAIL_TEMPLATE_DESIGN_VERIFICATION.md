# تصميم بريد منصة المواظبة — تحقق محلي

التاريخ: 2026-10-08. طلب المستخدم: تحسين جميع قوالب البريد مع الحفاظ على هوية المنصة.
**النتيجة: PASS محلياً للتصميم والعقود المختبرة.** لا يمثل هذا قبولاً لصندوق بريد خارجي أو نشراً للإصدار.

## القوالب العشرة

| الرسالة | الغرض المعروض |
| --- | --- |
| `PARENT_ACCOUNT_ACTIVATION` | تفعيل حساب ولي الأمر وتوثيق البريد، مع اسم المدرسة |
| `RECOVERY_EMAIL_VERIFICATION` | توثيق البريد المستخدم في استعادة كلمة المرور |
| `PASSWORD_RESET` | إنشاء كلمة مرور جديدة |
| `DETAILS` | تفاصيل الباقة والحالة والمدة وسعر الباقة |
| `REMINDER_7` | اقتراب نهاية الاشتراك خلال 7 أيام |
| `REMINDER_1` | اقتراب نهاية الاشتراك خلال يوم أو أقل |
| `GRACE_STARTED` | بداية مهلة السماح وموعد نهايتها إن توفر |
| `EXPIRED` | انتهاء الاشتراك |
| `SUSPENDED` | إيقاف الاشتراك |
| `CANCELLED` | إلغاء الاشتراك |

`backend/common/email_templates.py` يجمع عرض HTML والنص البديل. يستعمل ألوان الواجهة القائمة:
الأخضر `#11786d`، الرأس `#183c37`، اللمسة الذهبية `#a56a22`، والخلفية `#f4f8f6`.
يعرض اسم «منصة المواظبة» وعبارة الهوية «إدارة مدرسية أكثر وضوحًا»؛ الهوية القائمة نصية،
فلا يعتمد ظهورها على صورة خارجية. عنوان واضح لكل غرض، زر إجراء، جدول بيانات مقروء،
رابط احتياطي باتجاه LTR، ونهاية صلاحية بتوقيت الرياض لروابط الحساب.

التخطيط عربي RTL وبجداول عرض وCSS أساسي داخل العناصر؛ تحسين المقاس الصغير في media query.
اختير هذا بناء على دعم Gmail الموثق للأنماط وmedia queries، دون اعتبار ذلك ضماناً
لتطابق كل عميل بريد: [Gmail CSS](https://developers.google.com/workspace/gmail/design/css).
لا خطوط أو صور خارجية أو عناصر تتبع أو JavaScript داخل رسائل البريد.

يُهرب اسم المدرسة ومحتوى الاشتراك والرابط داخل HTML. لا يدخل رمز الرابط إلى عنوان الرسالة
أو preheader، ولا تعرض رسائل الاسترداد اسم المدرسة أو بيانات الأبناء. تعرض رسائل الاشتراك
الحقول القائمة فقط؛ سعر الباقة لا يوصف كإيصال دفع. لا رقم جوال أو كلمة مرور مؤقتة أو
عناوين دعم مختلقة. رابط مراجعة الاشتراك مشتق من أصل التطبيق المحدد ويُحذف عند فساد الأصل،
مع بقاء الإرشاد النصي. الدخول واختيار المدرسة مطلوبان؛ لا تغيير تلقائي لسياق المدرسة.

## مكان التطبيق وحفظ العمل المتزامن

كانت رسائل الاشتراك والإكمال المدرسي في نسخة مستقلة عن تفعيل ولي الأمر الأحدث:

- `xmansx-parent-release-20261008`: طُبق التصميم على مزود التفعيل والتوثيق والاسترداد الحالي؛
  احتفظ اسم مرسل التفعيل باسم المدرسة وعنوان الإرسال القائمين. لم تعدل هذه المهمة
  الهجرة `0009` أو تقارير التحقق القديمة أو اختبار rollback الذي أضيف بالتزامن.
- `xmansx-school-email-20261008`: طُبق المصمم نفسه على التوثيق والاسترداد ورسائل الاشتراك السبعة،
  مع حفظ توسعة التسجيل وأول دخول وإكمال بريد الموظف القديم السابقة.
- `xmansx-email-design-20261008`: نسخة اختبار مستقلة من أساس
  `495edaf7ebc37fcd2e0128c2bdde27a2447351f2` لتفعيل ولي الأمر، مع تصميم البريد الجديد.

هذه تطبيقات محلية ضيقة لملفات العرض واختباراته. لا دمج وظيفي بين توسعة المدرسة
وتوسعة تفعيل ولي الأمر؛ دمج الإصدار الموحد وفحوصه الأوسع عمل لاحق. لم يُكتب إلى شجرة `xmansx`
الأصلية، ولم تستخدم مصدراً للبناء. لم يحدث commit أو push أو merge أو deployment أو إرسال
Resend/SMS خارجي من هذه المهمة. لا تغيير dependencies أو lockfiles أو إعدادات مزود الإرسال.
حد الطلب 16KiB والإبطال ومدد الرموز وإعادة الإرسال وحالات المزود وقواعد الاستحقاق محفوظة.

ودور التفعيل واسم المرسل، بإرسال محاكى.

وأسماء مدرسة/باقة طويلة. كل حالة تثبت عدم overflow أفقي أو page error، اتجاه RTL، عنواناً
واحداً، زر ارتفاعه 44px على الأقل دون قص، وصفر طلبات موارد خارجية. فُحصت صور الأنواع العشرة
على الجوال بصرياً، وكذلك نماذج الكمبيوتر. معرض HTML والصور بيانات صناعية وروابط `.invalid`.

انتهت الجولة الأولى للتصوير عند خمس صور بسبب screenshot timeout تحت حمل الاختبارات الثقيلة؛
نجحت الجولة الكاملة بعد انتهاء الحمل وبمهلة التقاط 60 ثانية. لم تخفف اختبارات العرض أو العرض

## المعاينة وإعادة التنفيذ

معرض محلي في كل نسخة: `tmp/email-template-design/previews/index.html`.
يعرض HTML والنص البديل لكل نوع. الأدلة والصور متجاهلة في Git؛ السكربتان ضمن ملفات مصدر المهمة.

```powershell
python scripts/preview_transactional_emails.py --output tmp/email-template-design/previews
# حزمة Playwright المثبتة في frontend، أو مسار نسخة الواجهة التي تملك node_modules:
node scripts/verify_email_previews.mjs --frontend frontend --previews tmp/email-template-design/previews
```

اختبارات نسخة التصميم بقاعدة وRedis خاصتين ومصدر read-only:

```powershell
$vf = @('-p','xmansx-email-template-tests','-f','docker-compose.parent-verification.yml','-f','docker-compose.email-template-verification.yml')
docker compose @vf up -d --wait postgres redis
docker compose @vf run --rm --no-deps tests pytest --reuse-db -q -rs -o cache_dir=/tmp/email-template-pytest-cache tests/test_email_templates.py tests/test_parent_email_provider.py tests/test_parent_email_activation.py
```

اختبارات نسخة المدرسة تستخدم مشروع `xmansx-school-email-tests` وملف overlay الموجود
`docker-compose.school-email-verification.yml`، والملفات `test_email_templates.py`،
`test_parent_email_provider.py`، `test_subscription_email_provider.py`،
`test_subscription_email_schedule.py`. لا تستعمل قاعدة التطبيق أو أسرار البريد الحقيقية.
