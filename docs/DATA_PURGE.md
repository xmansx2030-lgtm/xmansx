# الحذف النهائي (Permanent Purge) — كما نفذ في المرحلة 4.1

## من يحذف

`SCHOOL_MANAGER` **حصرًا** (فردي وجماعي) — VICE/COUNSELOR/TEACHER محجوبون (403، اختبارات + E2E)، و`PLATFORM_ADMIN` لا يملك مسارًا عبر Tenant APIs (أي دعم مستقبلي: صريح/مقيد/مسجل). لا `DELETE /students/{id}` — action صريح `purge` (وضوح في الكود والـ Audit).

## ماذا يحذف

- **DB:** سجل خطوات `PURGE_STEPS` بترتيب التبعيات (حاليًا: علامات الحضور ثم تعديلات الحضور — سجلتهما المرحلة 6 عبر `attendance/purge_integration.py` في `AppConfig.ready` — ثم القيود ثم الطالب) داخل `transaction.atomic` لكل طالب. **قاعدة ملزمة:** كل موديول قادم يملك بيانات طالب (أعذار/إنذارات/إجراءات/إحالات/إرشاد/مستندات) يسجل خطوته هنا — وإلا فشل الحذف بـ ProtectedError صاخبًا لا صامتًا (حقول الطالب في وحدة الحضور PROTECT عمدًا، واختبار يجرد الخطوات ويثبت الفشل الصاخب). جلسة الحضور نفسها تبقى — لا تحوي معلومات معرفة بالطالب.
- **التخزين:** سجل `PURGE_STORAGE_COLLECTORS` يجمع ملفات الطالب وتحذف **بعد** commit قاعدة البيانات (الملفات خارج الـ transaction). حذف الصفوف وحده ليس Purge كاملًا: فشل حذف ملف → `storage_objects_failed` والعملية `PARTIALLY_FAILED` (لا ادعاء COMPLETED) — الآلية مثبتة باختبارات fake storage (لا ملفات طلاب فعلية في الوحدات الحالية؛ المرفقات والمستندات تسجل جامعاتها عند بنائها). ملفات الاستيراد المؤقتة تحذف أصلًا بعد الاعتماد/الإلغاء (سياسة المرحلة 4).

## الحمايات

- الطالب ACTIVE لا يحذف (`STUDENT_ACTIVE_CANNOT_PURGE` 409) — التصنيف أولًا (يشمل «أضيف بالخطأ»: INACTIVE ثم Purge بنفس الصلاحية والتأكيد).
- **Preview إلزامي:** ملخص خادمي موثوق (`POST /student-purges/preview/`) + `confirmation_token` في Redis (10 دقائق، يستخدم مرة واحدة) — الواجهة تطلب كتابة «حذف N طالبًا» حرفيًا.
- **Stale:** بصمة (id+status) لكل التحديد؛ أي تغير بين المعاينة والتنفيذ → `PURGE_PREVIEW_STALE` (اختبار).
- **العزل:** معرف أجنبي → 404 ورفض العملية كلها؛ والمهمة نفسها تحذف من `job.school` حصرًا حتى لو تسللت معرفات.
- **التزامن:** قيد DB «Purge واحد PENDING/RUNNING لكل مدرسة» (`PURGE_ALREADY_RUNNING`) + حالة المهمة idempotent في Celery. حذف محذوف → 404 مضبوط.

## Celery والدفعات

`StudentPurgeJob` → `run_purge_job` بدفعات **50** (مضبوطة بقياس `benchmark_purge`، deleted=N مثبت):

| rows | purge | معدل | peak mem |

| 10 | 1.48s | 6.8/s | 0.8MB |

التقدم يحدث كل دفعة (الواجهة تعرض `128/186` بالـ polling — لا Request مفتوحًا).

## الخصوصية بعد الحذف

- عند الاكتمال **تمسح `student_ids` من الـ Job** — لا معرف قابل للربط يبقى.
- Audit: `STUDENT_PERMANENTLY_PURGED` (فردي، بلا target_id) و`STUDENT_BULK_PURGE_STARTED/COMPLETED` — المحتوى: school/actor/timestamp/أعداد/سبب فقط. **لا** اسم ولا هوية ولا جوال ولي أمر ولا رقم طالب (اختبارات نصية).
- **لا استعادة:** البيانات المحذوفة لا تستعاد من المنصة (يعرض للمدير قبل التأكيد) — النسخ الاحتياطية التشغيلية للبنية خارج نطاق هذه الآلية وتخضع لسياسات المرحلة 20.
