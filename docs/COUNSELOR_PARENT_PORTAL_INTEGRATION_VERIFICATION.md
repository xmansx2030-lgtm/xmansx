# استكمال تكامل المرشد مع بوابة ولي الأمر

التاريخ: 2026-10-09. الفرع المحلي `codex/family-search-20261009`، أساس العمل
`f50ac7b`. التنفيذ في شجرة العمل المعزولة، مع الحفاظ على تعديلات بحث الأسر السابقة.

## السلوك بعد التعديل

- يتضمن ملف الحالة تبويب **متابعة الأسرة** وزراً للوصول إليه. ينشر المرشد توصية
  من الحالة المفتوحة دون كتابة أرقام الطالب والحالة؛ هوية الطالب ثابتة ومعروضة.
- صفحة إدارة أولياء الأمور للمرشد توفر البحث باسم الطالب في حالاته المسندة،
  مع ترقيم الصفحات وروابط مباشرة إلى متابعة الأسرة. البحث خادمي قبل الترقيم،
  بعد توقف الكتابة 350ms. تحفظ صلاحيات المدير والوكيل القائمة.
- تعرض بطاقة المنشور اسم الطالب، الإجراء المطلوب، الموعد، عدد تأكيدات الاطلاع،
  عدد تأكيدات التنفيذ مقابل أولياء الأمر النشطين المتلقين، وآخر وقت تنفيذ.
  يظهر التأخر عندما يبقى إجراء غير منفذ بعد الموعد.
- يسجل النشر والاطلاع والتنفيذ والسحب أحداثاً في الخط الزمني للحالة، مع عنوان
  التوصية. يحدث آخر نشاط للحالة عند الحدث الفعلي. تكرار الاطلاع أو التنفيذ
  أو السحب لا يكرر الحدث ولا يعيد احتساب التنفيذ.
- تعرض لوحة المرشد مؤشري **بانتظار إجراء الأسرة** و**متابعة الأسرة المتأخرة**،
  ورابطاً لمتابعة التوصيات. المؤشرات تحسب التوصيات في الحالات الحية المسموح له
  رؤيتها، لا عدد أولياء الأمر؛ التوصية ذات أكثر من ولي أمر تبقى معلقة إذا بقي
  أحد المتلقين النشطين دون تنفيذ. يستبعد المنشور المسحوب والعلاقات غير النشطة.
- تأكيد الاطلاع مستقل عن تأكيد التنفيذ. لا تغلق الحالة أو تنفذ أنشطة خطة
  الإرشاد تلقائياً بسبب تفاعل ولي الأمر.
- حقل المستند الإداري مخفي عن المرشد، ويبقى متاحاً للأدوار الإدارية المصرح بها.
  المنع الخادمي القائم محفوظ. المنشور المسحوب موسوم، ولا يعرض زر سحب جديد.

## الصلاحيات والخصوصية

المرشد ينشر ويسحب من حالاته المسندة فقط؛ لا تتوسع صلاحيات مراجعة أعذار الأسرة
أو المستندات الإدارية. حالة مرشد آخر تبقى غير متاحة حتى عبر المسار المباشر،
ولا يمكن توسيع نتائج البحث أو المؤشرات بفلتر مرشد أو مدرسة من العميل.

لا ينسخ ملخص الحالة أو الجلسات إلى بوابة ولي الأمر. أحداث الأسرة تحتوي فقط
معرف المنشور وعنوانه المصرح، وبيانات الحالة وتفاصيل تأكيدات الموظف تبقى في
استجابة الموظف، ولا تضاف إلى استجابة ولي الأمر.

يُجمع تقدم تنفيذ الأسرة باستعلام مجمع واحد لكل صفحة، مع تحقق المدرسة والطالب
ومالك العلاقة النشطة. لا يضاف استعلام لكل بطاقة. تستمر الواجهة في إعادة الجلب
عند العودة إليها وبفاصل اللوحة القائم، وتبطل الاستعلامات المرتبطة بعد النشر والسحب.

المجموع **141 اختباراً ناجحاً**. اختبارات الخادم تشمل رحلة كاملة أيضاً تحت دور
PostgreSQL `NOSUPERUSER NOBYPASSRLS` مع تفعيل RLS، وعدم تكرار الأحداث،
تعدد أولياء الأمر، استبعاد العلاقة الملغاة والحالة المغلقة، وعدم مساواة الاطلاع
بالتنفيذ، وعدم توسيع نطاق الحالة بعد نقل مسؤوليتها. اختبار الاستعلام المجمع
يتحقق من بطاقتين في استعلام تقدم واحد.

تجارب المتصفح استخدمت قاعدة مستقلة `counselor_portal_audit_20261009` ومدرسة
وطلاباً وحسابات صناعية. بدأت من البحث عن الطالب، ثم النشر من الحالة بموعد،
ظهور المؤشر المعلق والمتأخر، انتقال ولي الأمر من الإشعار إلى ابنه، الاطلاع والتنفيذ،
عودة المرشد لمشاهدة التنفيذ والأحداث، انخفاض المؤشرات، ثم سحب التوصية.
لم يظهر الملخص الداخلي، ولم يوجد تجاوز أفقي أو أخطاء JavaScript في الصفحات المفحوصة.
تجارب المتصفح تستخدم مالك قاعدة الاختبار؛ إثبات RLS المذكور يخص اختبارات الخادم المقيدة.

## إعادة التشغيل والأدلة المحلية

```powershell
docker compose -f docker-compose.parent-verification.yml run --rm --no-deps tests pytest --reuse-db -q tests/test_parent_requests.py tests/test_counseling.py tests/test_counseling_api.py -o cache_dir=/tmp/counselor-integration-pytest
```

ومن مجلد `frontend`:

```powershell
npm run test -- --run src/features/counseling/counseling.test.tsx src/features/counseling/counselorFamily.test.tsx src/features/parent/parent.test.tsx --maxWorkers=1
npm run build
npx playwright test --config tmp/playwright.counselor-integration.config.ts
```

اختبار Playwright الأخير يحتاج البيئة والبيانات الصناعية المحلية المحفوظة في
`tmp/counselor_audit_settings.py` و`tmp/counselor_portal_audit_seed.py` وملف fixture
الخاص بها، وخادمي التجربة على المنفذين 8019 و5187. السكربت وجولة المتصفح محليان
في `frontend/tmp/`؛ اختبارات الخادم وVitest الجديدة ضمن ملفات المشروع.
