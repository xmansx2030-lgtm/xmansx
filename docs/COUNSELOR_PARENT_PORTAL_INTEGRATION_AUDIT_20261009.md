# مراجعة تكامل لوحة المرشد مع بوابة ولي الأمر

هذا تقرير المراجعة السابقة للإصلاح. عولجت الفجوات لاحقاً محلياً بطلب المستخدم؛
تفاصيل التنفيذ والتحقق في [تقرير استكمال التكامل](COUNSELOR_PARENT_PORTAL_INTEGRATION_VERIFICATION.md).

التاريخ: 2026-10-09. أساس الكود `f50ac7b`، الفرع المحلي
`codex/family-search-20261009` في شجرة العمل المعزولة.

## النتيجة

التكامل يعمل لنشر توصيات مصرح بها للأسرة، وصول الإشعار، تأكيد الاطلاع،
تحديد موعد، وسحب المنشور. لكنه غير مكتمل من جهة متابعة المرشد داخل ملف الحالة:
النشر وتفاعل الأسرة لا يظهران في خط الحالة الزمني أو مؤشرات اللوحة، وحالة تنفيذ
الإجراء لا تعرض للمرشد. الوصول إلى نموذج النشر يتطلب إدخال أرقام داخلية يدوياً.

هذه مراجعة ببيانات تجريبية حسب طلب المستخدم. لم يُعدل كود المنتج لعلاج النتائج،
ولم تُجر عمليات كتابة على الإنتاج أو نشر. تعديلات بحث الأسر السابقة محفوظة.

## بيئة الاختبار وحدود الدليل

- PostgreSQL مستقل باسم `counselor_portal_audit_20261009`، به مدرسة صناعية،
  طالب للحالة المسندة، طالب لمرشد آخر، مرشدان، وكيل، وولي أمر بعلاقة معتمدة.
- واجهة Vite على `http://127.0.0.1:5187` وخادم Django محلي على المنفذ `8019`.
  الطلبات حقيقية للواجهة والخادم وقاعدة البيانات، بلا محاكاة ردود API في تجارب المتصفح.
- استُخدم دور مالك قاعدة البيانات في هذه التجربة؛ النتائج تثبت حدود صلاحيات API
  المعنية، ولا تعد إثباتاً مستقلاً لتطبيق PostgreSQL RLS بدور مقيد.
- عُزلت مفاتيح cache التجربة عن بقية الاختبارات. تكرار الدخول أثناء تطوير الاختبار
  شغّل حد الدخول المحلي، ثم أُعيدت الجولة بمفاتيح معزولة دون تغيير حماية المنتج.
- لا يتوفر في هذه المراجعة دليل رحلة حساب مرشد على الموقع الإنتاجي.

## الرحلة التي نُفذت

1. دخول مرشد الاختبار: لوحة الإرشاد تعرض حالته؛ حالة المرشد الآخر غير ظاهرة.
2. فتح ملف الطالب والخط الزمني: لا إجراء لنشر توصية للأسرة من داخل الملف.
3. الانتقال عبر القائمة إلى إدارة أولياء الأمور؛ يظهر للمرشد تبويب المحتوى المنشور.
4. إدخال رقم الطالب ورقم الحالة ونشر «فحص تكامل توصية المرشد»، مع نص مصرح
   وإجراء مطلوب؛ لم يُنسخ الملخص الإرشادي الداخلي.
5. دخول ولي الأمر؛ إشعار المنشور يفتح صفحة الابن الصحيحة وتبويب محتوى الأسرة.
6. تأكيد الاطلاع ثم تأكيد تنفيذ الإجراء من الإشعار؛ هذان إجراءان منفصلان.
7. العودة للمرشد: عدد تأكيدات الاطلاع يصبح 1، وتظهر هوية مختصرة ووقت التأكيد.
   تنفيذ الإجراء لا يظهر في بطاقة المنشور أو ملف الحالة.
8. نشر توصية إضافية بموعد `2026-10-11`؛ الموعد يظهر لولي الأمر. سحبها
   يجعلها تختفي من API المنشورات المتاحة لولي الأمر.

## الفجوات المثبتة

### 1. النشر منفصل عن سياق الحالة — أولوية متوسطة

ملف الحالة لا يوفر زر نشر للأسرة أو تبويباً لمحتواها. النموذج يطلب «رقم سجل
الطالب للنشر» و«رقم الحالة الإرشادية المسندة» بدلاً من البحث والاختيار أو تعبئة
بيانات الحالة المفتوحة. كذلك بطاقات المنشورات لا تعرض اسم الطالب أو الحالة.
هذا يصعّب الوصول للنشر ومتابعة عدة طلاب، حتى مع سلامة التحقق الخادمي.

المواضع: `frontend/src/features/counseling/CaseDetailPage.tsx:210`،
`frontend/src/features/parent/ParentManagementPage.tsx:1256` و`:1335` و`:1392`.

التوصية: إتاحة النشر من الحالة المسندة، مع هوية الطالب والحالة معبأتين ومثبتتين،
وعرضهما على المنشور. تُحفظ صلاحيات التحقق الحالية على الخادم.

### 2. تفاعل الأسرة لا يدخل متابعة الحالة — أولوية متوسطة

قاعدة البيانات بعد النشر والاطلاع والتنفيذ أثبتت:

| السجل الصناعي | القيمة UTC |
| --- | --- |
| آخر نشاط للحالة 1 | `2026-10-09 16:28:18.767144+00:00` |
| نشر التوصية 3 | `2026-10-09 16:29:38.167208+00:00` |
| عدد تأكيدات الاطلاع | `1` |
| تأكيد تنفيذ الإجراء | `2026-10-09 16:30:53.602441+00:00` |
| عدد أحداث الحالة بعد الرحلة | `0` |

واجهة الخط الزمني بقيت خالية من هذا التفاعل. `publish_family` ينشئ منشوراً
وسجل تدقيق وإشعاراً للأسرة، لكنه لا يسجل حدث حالة أو يحدث آخر نشاطها.
`case_timeline` يقرأ أحداث الحالة فقط. مؤشرات اللوحة تعتمد الحالات والإحالات
وطلبات المعلمين وأنشطة الخطة، دون توصيات الأسرة أو مواعيدها.

تنفيذ الإجراء مخزن في `ParentNotification.action_completed_at`، لكنه غير
معروض في استجابة منشورات الموظف أو بطاقة المنشور. تأكيد الاطلاع وحده لا يثبت التنفيذ.

المواضع: `backend/parents/request_services.py:402`،
`backend/parents/request_api.py:441`، `backend/counseling/selectors.py:105` و`:193`،
`frontend/src/features/parent/ParentManagementPage.tsx:1406`.

التوصية: تسجيل أحداث واضحة للنشر والاطلاع والتنفيذ والسحب في الحالة المسندة،
وإظهار متابعة الأسرة وحالتها وموعدها للمرشد. تحديد أثر ذلك على آخر نشاط ومؤشرات
التأخر يحتاج قراراً وظيفياً؛ لا يُعد تنفيذ الأسرة إغلاقاً تلقائياً للحالة.

### 3. حقل مستند لا يطابق صلاحية المرشد — أولوية منخفضة

النموذج يعرض للمرشد «رقم المستند المصرح (اختياري)»، بينما خدمة النشر تمنع
المرشد من نشر المستندات الإدارية وتخصصها للمدير أو الوكيل. النتيجة إتاحة مدخل
لا يمكن استعماله بهذه الصفة. ثبت الحقل بالواجهة، والمنع بمراجعة الخدمة؛ لم تُنفذ
في هذه الجولة محاولة مستند إداري فعلية بحساب المرشد.

المواضع: `frontend/src/features/parent/ParentManagementPage.tsx:1371`،
`backend/parents/request_services.py:449`.

التوصية: إخفاء الحقل عند استخدام دور المرشد، مع إبقاء المنع الخادمي.

  الحالة الصحيح `CASE_NOT_FOUND`، وليس مجرد 404 لمسار غير موجود.
- الفجوات أعلاه نتائج مراجعة وظائف وتجربة استخدام؛ نجاح الاختبارات لا يعني اكتمال
  الوظائف الناقصة. اختبارات الوحدات القائمة لا تغطي تكامل أحداث الحالة مع الأسرة.

أوامر الاختبارات:

```powershell

npm run test -- --run src/features/counseling/counseling.test.tsx src/features/parent/parent.test.tsx
npx playwright test --config tmp/playwright.counselor-audit.config.ts
```

الأمر الثاني والثالث من مجلد `frontend`. سكربتات البيئة والبيانات والجولة الحقيقية
محلية في `tmp/` و`frontend/tmp/`؛ تتطلب إعداد البيئة التجريبية المذكورة أعلاه.
أُوقفت خوادم التجربة بعد المراجعة، وتُركت الأدلة المحلية.
