# إنذارات الطلاب (المرحلة 11)

`StudentWarning` سجل إداري تاريخي: يصدر بقرار بشري صريح، ويحفظ صورة كاملة للحظة
الإصدار، ولا يحذف ولا يعاد حسابه أبدًا.

## الإصدار

`POST /api/v1/warnings/issue/` — الجسد: `student_id`, `warning_type`, `level`,
`notes?` فقط. **العميل لا يرسل** العتبة ولا المقياس ولا المصدر ولا أي snapshot
(‏mass assignment مرفوض — اختبار يحقن قيمًا مزورة ويثبت تجاهلها).

قبل الإنشاء يتحقق الخادم من: الدور، المستأجر، وجود القاعدة وتفعيلها، **إعادة حساب
الاستحقاق لحظة الإصدار** (لا ثقة بما عرضته الواجهة — القاعدة قد تتغير بين العرض
والضغط)، وعدم التكرار.

- مستوى غير مبلوغ → `WARNING_LEVEL_NOT_REACHED` (‏409) مع القيمة الحالية والحد.
- نوع موقوف → `WARNING_TYPE_DISABLED` (‏409).
- **النقر المزدوج/التزامن**: قيد فريد جزئي في قاعدة البيانات
  `UNIQUE(school, student, academic_year, warning_type, level) WHERE status='ISSUED'`
  داخل `transaction.atomic` → إنذار واحد لا اثنان، والثاني يرد `WARNING_ALREADY_ISSUED`.
- الإصدار **لا يمس** أي بيانات خام: الحضور والأعذار والوصول الصباحي كما هي (اختبار).
- **لا PDF هنا** — المستند مرحلة 12.

## Snapshot — جاهزية المرحلة 12

كل ما يحتاجه المستند محفوظ لحظة الإصدار، فتنتجه م12 من `warning_id` وحده:

- الحكم: `threshold_at_issue`, `metric_value_at_issue`.
- الطالب: `student_name_snapshot`, `grade_name_snapshot`, `section_name_snapshot`,
  `national_id_masked_snapshot` — **لا رقم هوية plaintext**.
- المقاييس: أيام الغياب الكامل (كلي/بدون عذر/بعذر)، حصص الغياب (كلي/بدون عذر)،
  التأخر الصباحي (مرات + دقائق)، تأخر الحصص (مرات + دقائق) — **عدادان منفصلان دائمًا**.
- السياق: `academic_year` (PROTECT) و`semester` (مرجعي).

اختبارات: تغيير الحدود بعد الإصدار، نقل الطالب لفصل آخر، وتغيير اسمه — كلها لا تمس
الـSnapshot.

## العذر بعد الإنذار (السيناريو الحاسم)

طالب بلغ 5 أيام بدون عذر وصدر له الإنذار الثاني، ثم اعتُمد عذر ليومين:

```text
metric_value_at_issue = 5      ← لا يتغير أبدًا
current_metric_value  = 3      ← يحسب عند العرض
metric_drifted        = true   ← الواجهة تنبّه: «تغيّر تصنيف بعض الأيام بعد الإصدار»
status                = ISSUED ← الإنذار يبقى: صدر فعلًا حين كانت البيانات 5
```

`get_warning_current_metric(warning)` يحسب القيمة الحالية بنفس مقياس الإنذار — ولا
يلمس الـSnapshot إطلاقًا. الإنذار لا يصبح «غير صالح» تلقائيًا؛ المعالجة الإدارية
(ملاحظة/إجراء) تأتي في مراحل لاحقة.

## الإلغاء

`POST /api/v1/warnings/{id}/void/` — **المدير حصرًا** وبسبب إلزامي. لا حذف نهائي
لسجل صادر (الخطأ يعالج بالإلغاء). يحفظ `voided_by_membership`, `voided_at`,
`void_reason`. الإلغاء مرتين → `WARNING_ALREADY_VOIDED`.

**سياسة موثقة:** الملغى **لا يحجز المستوى** — القيد الفريد مشروط بـ`status='ISSUED'`،
فيمكن إعادة إصدار نفس المستوى بعد تصحيح الخطأ (اختبار يثبت إنشاء صف ثانٍ مستقل مع
بقاء الملغى في السجل).

## العرض

- **لوحة «يحتاج متابعة»** (`/warnings`): بطاقتان (طلاب بلغوا حد الغياب / حد التأخر)
  + قائمة بالطالب والصف/الفصل والقيمة الحالية والمستوى المبلوغ والمستويات الصادرة،
  وزر إصدار **للمستحق فقط**. فلاتر: النوع، الصف، الحالة (مستحق/صدر/الكل).
  فرق صريح بين `DUE` و`ISSUED`.
- **تبويب الإنذارات في ملف الطالب**: ملخص (إنذارات الغياب/التأخر) + قائمة بالتاريخ
  والمستوى و«صدر عند N» + تفاصيل تعرض القيمة وقت الإصدار مقابل الحالية والانحراف،
  والصف/الفصل وقت الإصدار (من الـSnapshot لا القيد الحالي).

## التدقيق والحذف النهائي

- Audit: `WARNING_RULES_UPDATED`, `STUDENT_WARNING_ISSUED`, `STUDENT_WARNING_VOIDED`
  — المحتوى معرفات وأرقام فقط (لا اسم ولا هوية). **لا حدث لكل حساب استحقاق** (ضجيج).
- Purge (م4.1): «إنذارات الطالب» مسجلة في `PURGE_STEPS` و`student` بـ**PROTECT** —
  نسيان التسجيل يفشل صاخبًا. `WarningRule` بيانات مدرسة فلا تحذف مع الطالب.

## العزل والصلاحيات

كل الواجهات `SchoolScopedAPIView` بلا `school_id` من العميل؛ إنذار/طالب مدرسة أخرى
→ 404 (اختبارات + E2E)، ومدير في A ومعلم في B يعمل في A ويرفض في B.

## المرحلة 12 — من الإنذار إلى المستند

لقطة الإنذار كافية وحدها لإنتاج «الإنذار الأول/الثاني/الثالث» كمستند PDF رسمي:
مستند الإنذار **لا يعيد حساب أي مقياس** (مثبت بعدّاد استعلامات)، فتغيير القواعد أو
اعتماد عذر لاحقًا أو نقل الطالب لا يمس مستندًا صدر. نسخة أصلية واحدة لكل إنذار
(قيد فريد جزئي)، وإعادة الطباعة تعيد الملف المخزن نفسه ببصمته.

تسليم الإنذار لولي الأمر ليس أثرًا جانبيًا للإصدار: يسجل كإجراء
`WARNING_DELIVERED` صريح ([STUDENT_ACTIONS.md](STUDENT_ACTIONS.md)).
