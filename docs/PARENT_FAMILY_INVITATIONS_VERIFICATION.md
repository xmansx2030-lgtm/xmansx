# دعوة الأسرة المستخرجة من بيانات نور — تحقق التنفيذ

تاريخ العمل: 2026-10-09. أساس الكود `af8a3243da2c819b85292d92fa149bf736efdac7`،
وفرع العمل المحلي `codex/parent-family-invitations-20261009`.

الحكم: **PASS WITH ISSUES**. التنفيذ المحلي وقبول البيئة الصناعية المقيدة
ناجحان. إرسال الدعوات الخارجي يبقى opt-in؛ لم يختبر وصول SMS حقيقي في هذه المهمة.

## الرحلة المنفذة

1. يفتح المدير أو الوكيل **إدارة أولياء الأمور → الأسر والدعوات**.
2. تعرض القائمة اسم التواصل المدرسي، الجوال المقنع والأبناء المقترحين من الطلاب
   النشطين في المدرسة الحالية. يجمع النظام الأرقام الصحيحة بعد التطبيع؛ الأرقام
   الفارغة وغير الصحيحة لا تجمع طلاباً مختلفين في أسرة واحدة.
3. يراجع الموظف صفة ولي الأمر والرقم والأبناء، ويختار الأبناء ويكتب إثبات التحقق
   ويؤكد الاعتماد. اختلاف أسماء التواصل لا يعني تطابق الأشخاص ويظهر للمراجعة.
4. يحفظ النظام موافقة مستقلة لكل ابن، ثم يرسل **SMS واحداً للأسرة** باسم المدرسة
   ورابط دعوة خاص. يمكن مراجعة حتى20 أسرة في دفعة واحدة؛ حد الدعوة50 ابناً.
5. ولي الأمر الجديد يدخل البريد وكلمة المرور وتأكيدها؛ لا يدخل معرف طالب أو
   بيانات كل ابن. الموجود يسجل الدخول إلى حسابه الحالي؛ لا ينشأ حساب بديل ولا
   تتغير كلمة مروره أو جواله أو بريده الوظيفي.
6. إذا لم يملك الحساب بريد استرداد موثقاً، يرسل مسار البريد الحالي رابط توثيق
   شخصياً. تظهر شاشة الانتظار وتظل بيانات الأبناء محجوبة حتى POST التوثيق الصريح.
   الحساب الموجود ذو البريد الموثق يحتفظ به دون استبدال من بيانات دعوة مدرسية.

هذه إضافة لمسار الدعوة المدرسية. طلبات التسجيل والموافقات والتفعيل البريدي
السابقة تبقى مدعومة. رقم التواصل المستورد اقتراح للتجميع، وليس هوية الحساب
العالمي أو دليل ملكية كافياً لمنح صلاحية تلقائية.

## تمييز ولي الأمر المدعو

البطاقة التي لها دعوة تتميز بحافة وشارة نصية؛ لا يعتمد التمييز على اللون وحده.
يرى المدير والوكيل الاسم المعتمد، وقت الإصدار/الانتهاء، الأبناء الذين شملتهم
الدعوة، وهل أضيف أبناء لاحقاً لم تشملهم الدعوة السابقة.

| الحالة | المعنى |
| --- | --- |
| لم تُرسل دعوة | لا توجد دعوة محفوظة لهذا التواصل |
| بانتظار الإرسال / جارٍ الإرسال | موافقة محفوظة ومحاولة لم تنته بعد |
| دعوة مقبولة لدى مزود SMS | قبل المزود الطلب؛ ليس إثبات وصول للهاتف |
| فشل الإرسال | رفض محدد، أو لم تبدأ محاولة إرسال صالحة |
| نتيجة غير مؤكدة | قد يكون المزود استلم الرسالة؛ لا إعادة إرسال عمياء |
| انتهت الدعوة / دعوة ملغاة | الرابط لا يصلح للتفعيل |
| تغيرت البيانات — تحتاج مراجعة | أحد الأبناء أو إثبات التواصل لم يعد صالحاً |
| تم تفعيل الربط | استهلك صاحب الحساب الدعوة؛ توثيق بريد الاسترداد شرط وصول مستقل |

إعادة الإصدار تتطلب مراجعة جديدة، وتلغي الرابط السابق وأدلته غير المستهلكة.
لا تكشف واجهات الموظف الرمز أو الرابط السري أو بريد استرداد الحساب العالمي.

## الأمان وقاعدة البيانات

نموذجان إضافيان: `GuardianFamilyInvitation` و`GuardianFamilyInvitationChild`.
الأول يحفظ رقم التواصل مشفراً وبصمة HMAC وعرضاً مقنعاً وبصمة bearer فقط؛ الثاني
يربط كل ابن بإثبات موافقة/تفعيل مستقل موجود، ولا ينسخ مواظبة الطالب.

`parents0010` إضافة ذرية: الجداول والفهارس والقيود، FORCE RLS وثماني سياسات
مدرسية محددة، وحراس SQL للمدرسة والابن والموافقة وعدم استبدال الإثبات/إعادة
استهلاكه. الرمز الفردي المشتق لا يمكن استعماله عبر API التفعيل الفردي لتجاوز
سلامة الأسرة. ليس في الهجرة SECURITY DEFINER أو إعفاء عام جديد من RLS.

الرمز عشوائي256bit ومدة الدعوة24ساعة افتراضياً، ضمن300–172800ثانية.
روابط Fragment تمسح من History، مع no-referrer/no-store، ودون تخزين في
TanStack keys أو browser storage أو Audit أو وسائط Celery. GET لا يفعّل دعوة.

ترتيب الأقفال: المدرسة KEY SHARE، قفل PostgreSQL advisory خاص ببصمة التواصل،
الطلاب مرتبين، الطلبات، التفعيلات، ثم الدعوة والحساب. الدفعات تقفل بصمات الأسر
مرتبة قبل الطلاب. مسار حذف الدعوات المستخدم في purge يتبع الترتيب نفسه قبل
الحذف المتسلسل. الحذف يبطل أدلة الإخوة غير المستهلكة قبل إزالة الدعوة.

يُعاد فحص الطالب النشط، دمجه، المعرف، إصدار التواصل، موافقة المدرسة والاشتراك
وحظر المستلم قبل الإرسال والتفعيل. حارس Noor الموجود يلغي تفعيل الابن عند
تغير التواصل حتى في `update()`؛ لا تمنح دعوة الأسرة بقية الأبناء جزئياً إذا
أصبح أحد إثباتاتها غير صالح. التفعيل ذري ويستهلك مرة واحدة تحت التزامن.

الواجهة تخفي بطاقات الأبناء عند خطأ صلاحية القراءة وتتوقف عن polling؛ لا
تعرض بيانات query قديمة بعد سحب الصلاحية.

## حدود التسليم

لا إرسال SMS أو بريد خارجي ضمن هذه المهمة؛ المزود الحقيقي يحتاج قبولاً مصرحاً
به لاحقاً. لا push أو merge أو نشر. لا تغييرات في مصادر SMS الغياب أو قواعد
الحضور/الغياب أو Noor أو الاستئذان الإداري/الحارس. لا استئذان إلكتروني للأهل.
تغيير `User.mobile` والاستعادة المركزية غير المثبتة يظلان مغلقين.

تغييرات المستخدم الأصلية56 مساراً، وتغييرات قالب البريد الست في شجرة الإصدار
الأخرى، خارج هذا الفرع؛ لا تُدمج تلقائياً. النتيجة هنا محلية ويمكن دمجها لاحقاً
بعد مراجعة تعارض الإعدادات والخدمات واختبارات التوافق.
