# استيراد المعلمين — كما نفذ في المرحلة 5

## الملف والأمان

‏`.xlsx` فقط — **نفس حماية استيراد الطلاب** عبر `common/excel_security.py` المشترك (المستخرج في هذه المرحلة): حجم/zip bomb/ماكرو مرفوض/لا تنفيذ صيغ. الأعمدة: اسم المعلم + رقم الجوال (إلزامية) + رقم وظيفي ومسمى (اختيارية)، مع اقتراح mapping من aliases وواجهة مطابقة يدوية. تطبيع الجوال بإعادة استخدام `normalize_mobile` (المرحلة 2) — لا نسخة جديدة.

## الدور الافتراضي — قرار أمني

كل سجل مستورد يمنح **TEACHER فقط**. الملف لا يمنح أدوارًا إدارية أبدًا (منع Privilege Escalation من ملف خاطئ) — الأدوار الأخرى من واجهة الموظفين بصلاحية المدير.

## سلوك جديد/موجود

| الحالة | التصنيف | الاعتماد |
|---|---|---|
| جوال غير موجود | NEW | User جديد + كلمة مؤقتة + `must_change_password` + عضوية **ACTIVE** + TEACHER + Profile |
| موجود عالميًا بلا عضوية هنا | EXISTING_USER_INVITE | إعادة استخدام User + عضوية **INVITED** + TEACHER + Profile — كلمة مروره واسمه العالمي **لا يمسان** |
| عضو ACTIVE بلا TEACHER | ADD_TEACHER_ROLE | إضافة الدور فقط (COUNSELOR يبقى) |
| عضو ACTIVE ببيانات مختلفة | PROFILE_UPDATE | تحديث Profile + Audit |
| مطابق تمامًا | EXISTING_UNCHANGED | لا شيء |
| دعوة قائمة | INVITATION_PENDING | لا دعوة ثانية |
| DECLINED/SUSPENDED/LEFT | NEEDS_MANUAL_ACTION | لا إعادة دعوة صامتة — Reinvite صريح من الواجهة |

**الخصوصية (قرار موثق):** المعاينة تقول فقط «يوجد حساب مرتبط بهذا الرقم وسيُدعى» — لا أسماء مدارس أخرى ولا أدوار فيها (اختبار يثبت عدم تسرب اسم المدرسة الأخرى)، ولا API بحث حر عن وجود جوال — المطابقة داخل workflow الاستيراد المراقب والمسجل فقط.

## كلمات المرور المؤقتة

- توليد: `secrets.token_urlsafe(9)` — cryptographically secure.
- تعرض **مرة واحدة فقط** في استجابة الاعتماد («ستظهر مرة واحدة فقط») — **لا تخزن plaintext** في Job/summary/staging/Audit/logs (اختبار مسح شامل). لا Export للملفات (قرار: مؤجل — العرض الواحد يكفي).
- الحساب الموجود: لا تعرض ولا تغير كلمة مروره ولا حالتها — مدير المدرسة لا يعيد تعيين كلمات مرور عالمية.

## الاعتماد والحمايات

نفس نمط المرحلة 4: `transaction.atomic` + select_for_update + status gates (`STAFF_IMPORT_ALREADY_COMMITTED`) + **إعادة تصنيف كاملة عند الاعتماد** (User/Membership/Roles/Profile) → أي انحراف = `STAFF_IMPORT_PREVIEW_STALE` مع معاينة محدثة مثبتة. سباق إنشاء User: قيد `UNIQUE(mobile)` + التقاط IntegrityError → إعادة جلب الموجود والتحول لمسار الدعوة. Celery: tenant من `job.school`، idempotent، وملف PII يحذف بعد الانتهاء.
