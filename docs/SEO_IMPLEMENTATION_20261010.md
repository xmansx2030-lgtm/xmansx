# تحسين SEO لمنصة المواظبة

تاريخ التنفيذ: 2026-10-10. النطاق الرسمي: `https://mowadhabah.com`.
شجرة العمل المستقلة: `xmansx-seo-20261010`، الفرع `feat/platform-seo-20261010`.
بدأت من `origin/main` عند `233f78f`، دون نقل تغييرات السعة والطباعة والأعمال الأخرى
من شجرة `xmansx` الرئيسية.

## المشكلة المثبتة على الموقع العام

قبل التعديل، أعادت الصفحة الرئيسية HTML بطول 1120 حرفًا وجذر تطبيق فارغ.
وأعاد كل من `/robots.txt` و`/sitemap.xml` حالة 200 بمحتوى `text/html` لصفحة التطبيق،
دون ملف زحف أو خريطة XML صحيحة. لم توجد روابط canonical أو بيانات مشاركة أو JSON-LD.
تحوّل `www.mowadhabah.com` إلى النطاق الرئيسي؛ ظل عنوان Render يعرض التطبيق أيضًا.

## التحسينات

- توليد HTML للمحتوى العام من مكونات React نفسها أثناء البناء، دون استدعاء
  API الإنتاج أو تحميل بيانات طلاب أو مدارس. تصل النصوص والروابط لمحرك البحث
  والزائر عند أول استجابة، حتى دون JavaScript.
- ست صفحات عامة فعلية: الرئيسية، `/features/attendance`،
  `/features/student-follow-up`، `/features/reports`،
  `/features/parent-portal`، `/features/qr-attendance`.
- لكل صفحة عنوان ووصف مختلفان، وcanonical ثابت على النطاق الرسمي، وOpen Graph
  وTwitter Card وصورة الهوية العامة. لا تدخل معاملات التتبع أو رموز التفعيل
  في canonical أو البيانات المنظمة.
- بيانات JSON-LD من نوع Organization وWebSite وWebPage، وBreadcrumbList
  لصفحات الخدمات. لا توجد تقييمات أو أسعار أو عروض أو بحث داخلي غير موجودة.
- محتوى عربي يشرح الوظائف المتاحة، وأسئلة شائعة ظاهرة، وروابط داخلية بين الخدمات.
  تبقى الأسعار والقيود والاشتراك من الكتالوج الحي؛ لا تؤخذ نسخة قديمة أثناء البناء.
- `robots.txt` عام لكل برامج الزحف، يسمح بالمحتوى العام وموارد العرض ويمنع API
  والوسائط الخاصة. تبقى صفحات الحساب قابلة للزحف حتى تُقرأ تعليمات noindex.
- خريطة XML تضم الصفحات العامة الأساسية فقط. لا توجد تواريخ lastmod مصطنعة
  أو صفحات طلاب أو حسابات أو روابط تفعيل أو تسجيل QR في الخريطة.
- ترسل الصفحات الخاصة noindex وnofollow وnosnippet داخل HTML وفي X-Robots-Tag.
  تنتقل بيانات الصفحة عند التنقل الداخلي، وتحذف canonical وبيانات المشاركة
  وJSON-LD عند الوصول إلى صفحة خاصة. تبقى المصادقة والصلاحيات في مساراتها الحالية.
- يعيد Nginx حالة 404 للروابط العامة المجهولة، مع صفحة عربية وتعليمات noindex.
  يحوّل الشرطات النهائية للصفحات العامة و`/index.html` إلى الرابط الأساسي.
- تحميل مسبق لخطي العربية 400 و700 في الصفحات العامة وضغط XML مع ملفات النصوص.
  لا تنتظر صفحة الهبوط اكتمال فحص الجلسة؛ يبقى تحويل المستخدم المسجل إلى
  مساحة حسابه كما كان.
- يحافظ العامل الخدمي على بداية التطبيق دون اتصال باستخدام `app.html` الخاص،
  ويقرأ ملفات الزحف والخريطة من الشبكة. تظل API بنمط NetworkOnly. تُخزّن الصفحة
  الرئيسية على `/` بدل alias الذي يعيد301، حتى يكتمل تثبيت العامل الخدمي.
- تسمح سياسة CSP فقط ببصمات JSON-LD التي وُلّدت أثناء البناء، دون `unsafe-inline`
  أو توسيع مصادر JavaScript المسموح بها.
- أضيف فحص المخرجات واختبار Nginx والمتصفح إلى CI، إلى جانب اختبارات SEO
  التي يكتشفها Vitest تلقائيًا. يشغّل GitHub CI هذه الفحوص عند فتح طلب الدمج
  وعند نشر الإصدار المدمج على `main`.

## إعدادات البناء

القيم العامة التالية متاحة عبر Vite أو Docker build arguments:

| المتغير | القيمة الافتراضية / الاستخدام |
|---|---|
| `VITE_SITE_URL` | `https://mowadhabah.com`؛ أصل HTTPS فقط دون مسار أو معاملات |
| `VITE_SEARCH_INDEXING` | `true` للإنتاج، و`false` لصور التجربة وstaging |
| `VITE_GOOGLE_SITE_VERIFICATION` | رمز HTML الذي يقدمه Google Search Console |
| `VITE_BING_SITE_VERIFICATION` | رمز HTML الذي يقدمه Bing Webmaster Tools |

هذه قيم تُقرأ وقت البناء. تغييرها يتطلب إعادة بناء الواجهة. لا يكفي تغيير
متغير داخل حاوية Nginx المبنية مسبقًا. إعداد التطوير يرسل noindex، وعند بناء
staging بقيمة `false` ترسل الصفحات العامة noindex، وتكون الخريطة فارغة والزحف ممنوعًا.

```powershell
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test -- --maxWorkers=1 --pool=threads src/seo/seo.test.tsx src/features/public/PublicPages.test.tsx src/features/auth/guards.test.tsx src/app/cacheSafety.test.ts src/app/pwaAssets.test.ts
npm run build
npm run seo:check
```

اختبارات المتصفح تقبل واجهة محلية معزولة فقط، وتستخدم طلبات API وهمية دون
إرسال رسائل أو تعديل بيانات حقيقية:

```powershell
docker build --target prod -t xmansx-frontend:seo-20261010 frontend
docker run -d --name xmansx-seo-preview-20261010 -p 127.0.0.1:18090:80 -e BACKEND_HOSTPORT=host.docker.internal:9 xmansx-frontend:seo-20261010
cd frontend
npm run seo:test
```

## التحقق والمخرجات

يسجل `seo:check` سلامة XML والصفحات الست والعناوين وcanonical والروابط الداخلية
وبصمات CSP وخصوصية HTML الخاص وملفات العامل الخدمي. يفحص `seo:test` استجابات
Nginx و404 و301 والصفحات دون JavaScript، والتنقل إلى تسجيل الدخول وروابط التفعيل،
وعروض 390 و768 و1440 بكسل، وتثبيت العامل الخدمي دون تخزين API الخاص.

النتائج النهائية المحلية:

| الفحص | النتيجة |

| ESLint وTypeScript | ناجحان |

| بناء Vite وPWA | ناجح؛ 6 صفحات عامة و130 مدخلًا في precache |

معرّف صورة التحقق المحلية من تحسينات SEO، قبل تحديث نصوص واتساب، `xmansx-frontend:seo-20261010`:
`sha256:dd791b888e2c7df336f007cd9d0d00f71989b5d64807e398b113e68bbc3b32aa`.
بُنيت صورة التحقق من ملفات تحسين SEO في هذه الشجرة، وشُغلت اختبارات المتصفح عليها عبر

سكربتات CSP في رحلة التنقل المختبرة.

كشف اختبار تثبيت العامل الخدمي أولًا أن 301 على `index.html` يمنع precache؛
صُححت قائمة التخزين لتستخدم `/`، ثم نجح اختبار التثبيت والجولة النهائية كاملة.
أُعيد تشغيل Vitest بعامل threads واحد بعد مهلة بدء العمال المتوازين على الجهاز؛
النتيجة المذكورة أعلاه هي الجولة الناجحة بعد اكتمال التعديلات.

## رسائل واتساب والاسم الرسمي

وُحدت صياغة روابط التواصل في `frontend/src/utils/supportWhatsApp.ts` على اسم
«منصة المواظبة»، مع التحية وسبب التواصل وسطر الشكر. تحدد الصفحة سبب الطلب:
تسجيل الدخول، تغيير كلمة المرور المؤقتة، الاستفسار عن الخدمات والباقات،
تسجيل المدرسة، المساعدة في اختيار باقة، أو طلب الاشتراك. تتضمن طلبات الباقات
اسم الباقة، ويضاف اسم المدرسة في صفحة اشتراك المدرسة. بقي رقم الدعم
`0537720207` نفسه، وحُذف `XMANSX` من التذييل العام أيضًا.

بعد تحديث الرسائل نجحت الاختبارات الـ45 الموجودة في ملفات الدخول وتدفقات
المصادقة والصفحات العامة واشتراك المدرسة، إضافة إلى ESLint وبناء الإنتاج
وفحص `seo:check`. فُحص HTML العام الناتج: الرسائل تتضمن الاسم الرسمي وسبب
التواصل، ولا تتضمن الاسم القديم. لا تفتح هذه الفحوص محادثات فعلية ولا ترسل رسائل.

## الخطوات التشغيلية بعد نشر التغيير

كان التحقق المذكور أعلاه محليًا؛ يُثبت الرفع والدمج والنشر بواسطة SHA وفحوص
GitHub وسجلات Render وفحص النطاق الرسمي. لا تشمل تغييرات الكود تسجيل ملكية
جديدة لدى محركات البحث.
بعد نشر النسخة يجب التحقق من الملفات على النطاق الرسمي، ثم إثبات ملكية
`mowadhabah.com` في Google Search Console وBing Webmaster Tools، وإرسال
`https://mowadhabah.com/sitemap.xml`، وطلب فحص الصفحة الرئيسية وصفحات الخدمات.
تتيح رموز HTML الاختيارية إثبات الملكية دون إضافة أسرار إلى المستودع؛ وإذا
كانت ملكية DNS مثبتة مسبقًا، فلا يلزم رمز HTML.

المعيار التشغيلي: استجابة 200 وHTML مقروء لكل صفحة عامة، XML صحيح للخريطة،
robots نصي، noindex للصفحات الخاصة، 404 للرابط غير الموجود، ثم متابعة تقارير
الفهرسة والأداء وCore Web Vitals في حسابات محركات البحث. لا تُثبت هذه الفحوص
فهرسة فعلية ولا ترتيبًا محددًا قبل ظهور دليل من محرك البحث نفسه.
